# 技術記事・ドキュメント執筆

## 手順

1. 対象コードを調べ、実在するシンボル名・パス・CLI flag と処理の根拠を集める。コードベースを単語帳とし、識別子は意訳せずバッククォートで書く。
2. 読み手と目的に合わせて構成を決め、事実と未確認事項を分けてドラフトを書く。技術文書の構成は `technical-writing`、章・節をまたぐ論証設計は `japanese-tech-writing` の担当とする。
3. 構成と技術的主張を確定した後、`slop-word-refactor` だけで表現を整える。旧推敲 skill を連鎖起動しない。既に表示・保存 Hook が同じ本文を処理していれば保持条件の検査だけを行う。
4. 原文と根拠を照合し、識別子、数値、因果、条件、不確実性、引用、Markdown 構造が保たれていることを確認する。

PR は `rules/pr-body.md` に従い、仕様整理は `spec-ready` に従う。文体の追加ルールや独自の禁止語辞書はここに置かない。

`slop-word-refactor` が利用できない場合は、同じ保持条件に従って表現だけを手動で整える。実行していない検査を実行済みとしない。
