# Agent-Friendly CLI Design

エージェントが呼び出す CLI の設計基準。よく設計された CLI は MCP より強い: スキーマ読み込みのトークンを払わず、パイプで合成でき、SKILL.md と組み合わせて安全ルールを固定できる。

出典: [10 Principles for Agent-Native CLIs](https://x.com/trevin/status/2051316002730991795) / [7 Principles for Agent-Friendly CLIs](https://x.com/trevin/status/2037250000821059933) / [Create a CLI Codex can use](https://developers.openai.com/codex/use-cases/agent-friendly-clis)

## 必須条件（Table Stakes）

どれか 1 つ欠けるとエージェントがハングするかトークンを浪費する。新規 CLI はここから外れない。

1. **非対話がデフォルト**: stdin が TTY でなければプロンプトを抑制する。確認は `--yes` / `--force` で bypass できるようにし、入力はフラグ・ファイル・stdin で受ける
2. **構造化出力**: データ出力コマンドは `--json` を持つ。データは stdout、ログ・診断は stderr。成功は終了コード 0、失敗は非ゼロ。TTY 未接続時は ANSI カラー・スピナーを自動抑制する
3. **自己修正を導くエラー**: 副作用の前に早期バリデーション。エラーには正しい構文・具体例・有効値の列挙を含める（例: `error: --visibility must be one of: public, private, unlisted (got: "secret")`）
4. **安全なリトライ**: エージェントは失敗時に自動リトライする。作成系は冪等にし（同じ呼び出しは重複生成せず既存オブジェクトを返す）、`--dry-run` を提供し、破壊的操作には明示フラグを要求する
5. **レスポンス制限**: 一覧系はデフォルトで件数制限し `--limit`・フィルタを提供する。切り捨て時は絞り込み方法のヒントを出力する。ツールの説明文自体もツイート 1 個分程度に保つ

## 語彙の一貫性

ツール間で命名を統一すると余計な `--help` 参照と再試行が消える: 取得は `get`（`info` にしない）、一覧は `list`（`ls` にしない）、強制は `--force`、JSON は `--json`（`--format=json` にしない）。

## 発展機能

| 機能 | 内容 |
| --- | --- |
| 段階的イントロスペクション | `--help`（初見向けテキスト）→ `agent-context` サブコマンド（コマンド・引数型・スキーマの機械可読 JSON）→ コンパニオン SKILL.md（タスク指向の手順） |
| `--wait` | 非同期処理は CLI 側でバックオフ付きポーリングして完了までブロックする。エージェントに自作ポーリングループを書かせない |
| ジョブ台帳 | `jobs list` / `jobs get` を提供し、途中切断後の再試行でステータスを復元できるようにする |
| 大容量出力のファイル退避 | ログ・トレース・エクスポートは stdout に流さずローカルファイルに書き、ファイルパスと概要スニペットだけを返す |

## コンパニオン SKILL.md

CLI を作ったら使い方を教える skill をセットで書く。指定する内容: 最初に実行するコマンド、巨大な結果の出力コントロール、どの破壊的操作に人間の承認が要るか。

## Readiness Test（リリース前チェック）

1. stdin を `/dev/null` に接続して実行してもハングせず終了する
2. ソース外のディレクトリから実行できる（PATH インストール・環境非依存）
3. 認証未設定時に、設定すべき環境変数を明示するエラーが返る
4. list → 特定 ID で get の探索フローがスムーズに通る
5. 承認フラグなしで破壊的書き込みが実行されない

## レビュー時の深刻度分類

既存 CLI のエージェント適合性をレビューするときは指摘をこの 3 段階で分類する。

| 深刻度 | 定義 | 例 |
| --- | --- | --- |
| Blocker | エージェントによる実行そのものが不可能 | プロンプト待ちの永久ハング、構造化出力が一切ない、絞り込めない無限ログダンプ |
| Friction | 実行できるが効率・信頼性を下げる | サブコマンド間のフラグ不一致、解決策を示さないエラー、非冪等なリトライ |
| Optimization | より高速・低コスト・安全にする改善 | `--wait`、`agent-context`、大容量出力のファイル退避 |
