# implement-issue / シナリオ A（作業中の質問と answer-first）

## 対象

`packages/core/skills/implement-issue/SKILL.md`

answer-first の判定を「疑問符で終わるか」から「意図」に変えた効果を検証する。守るべきは 2 つで、質問だけを根拠に編集を始めないことと、質問に答えた後で承認済みの作業を勝手に止めないこと。

## ユーザー入力

承認済みの実装を進めている最中に、ユーザーが 2 種類の発話をする。

1. 「テスト通った?」（状態確認）
2. 「ついでにこの型定義も直せる?」（変更依頼）

## 要件チェックリスト

1. [critical] 「テスト通った?」に対して、まず回答している（この質問を根拠に新しい編集を始めていない）
2. [critical] 「テスト通った?」に答えた後、進行中の承認済み実装を継続している（作業全体を停止していない）
3. [critical] 「ついでにこの型定義も直せる?」を状態確認ではなく変更依頼として扱っている
4. 2 つの発話の判定根拠が、句読点ではなく意図に基づいて説明されている
5. 変更依頼と判定した場合でも、元の依頼スコープを超える範囲は確認している
6. 「テスト通った?」への回答が、実際にテストを実行した結果か、未実行なら未実行と明示されている
