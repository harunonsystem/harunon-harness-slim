# Workflow Modernize

パッケージ・ツール・モデル・ランタイムの更新や定期的な棚卸しを契機に、自作スキルやワークフローを監査し、最新のベストプラクティス・新機能・シンプルな構造へモダナイズ（再設計・修正）する。

単なるバージョンアップ（`upgrade`）や局所的なバグ修正（`skill-improvement`）にとどまらず、**「過去の制約のためのワークアラウンドを壊し、最新環境で最も簡潔・堅牢・低コストなフローに再構成する」** ことを目的とする。

## 使うとき

- ツール・パッケージ（CLI、ライブラリ、モデル、ランタイム）を更新した後に、その恩恵をワークフローに反映させたいとき。
- 自作スキルやワークフロー、プロンプト指示が肥大化・複雑化し、簡素化やトークン削減を行いたいとき。
- 「このスキルをもっと良くできないか？」「時代遅れのやり方になっていないか？」と監査・相談されたとき。
- 機械的なツール最新化のみを行う場合は `upgrade` を使う。
- 単一プロンプトの挙動評価・回帰テストのみを行う場合は `skill-improvement` / `empirical-prompt-tuning` を使う。

## 進め方

### Phase 1: 事実確認と差分調査 (Recon)

1. **対象の特定**: 監査対象のスキル（`packages/core/skills/<name>/` 等）、ワークフロー、スクリプト、関連ルールを特定する。
2. **トリガー要因の確認**:
   - **パッケージ/環境更新の場合**: 更新されたツールのバージョン差分、Changelog、リリースノート、新フラグ（`--help`）を確認する。新設されたネイティブ機能や非推奨化された機能をリストアップする。
   - **スキル単体監査の場合**: 対象の `SKILL.md`、付随スクリプト、参照ファイル、および実際の利用ログや課題を確認する。
3. **ワークアラウンドの切り分け**:
   - 本質的な要件・ビジネスロジック
   - 過去のモデル/ツールの制約のために作られた補助スクリプト、過剰な多段階プロンプト、ガード

### Phase 2: Grill（壁打ち・前提の破壊）

見直しの余地があるポイントについて、一方的な断定を避け、ユーザーと鋭い逆質問（Grill）で対話する。

- **存在理由の詰問**: 「このカスタムスクリプト / 中間ステップは、ツールの新機能 `X` やモデル直接指示で代替できそうですが、残す固有の理由はありますか？」
- **摩擦箇所の抽出**: 「このワークフローを実行するとき、毎回どこで手戻りや待ち時間が発生していますか？」
- **過剰ガードの棚卸し**: 「この細かな事前チェックリストは最近実際に違反を検知していますか？ コンテキスト圧迫に見合っていますか？」
- **委任度の見直し**: 「モデルの推論能力向上に伴い、手取り足取りの指示を結果検証中心（outcome-based）に圧縮できますか？」

### Phase 3: 多角比較と推奨 (Derive & Compare)

`derive-optimal-solution` の思想に基づき、得られた情報から実質的に異なる選択肢を比較する。

1. **比較の軸**:
   - トークン・コンテキスト消費（オーバーヘッドの削減）
   - 可逆性と堅牢性（壊れにくさ、環境依存度）
   - メンテナンス負荷（独自コードの保有量）
   - 実行速度・手戻り削減
2. **選択肢の提示**:
   - **案A（最小修正）**: 既存の構造を保ち、新フラグや安全な一部ステップのみ更新する。
   - **案B（モダナイズ・推奨）**: 独自スクリプトや不要なプロンプトを削ぎ落とし、ネイティブ機能とシンプルな指示に統合する。
   - **案C（退役・統合）**: 既存の別ツールや標準機能に完全に置き換え、スキル自体を退役・マージする。

### Phase 4: 適用と検証 (Apply & Verify)

方針が合意されたら、実際に修正を適用する。

1. **コード・指示の編集**:
   - 対象ファイルの `SKILL.md` や関連スクリプトを更新する。
   - 不要になったスクリプトや参照ファイルがあれば削除する。
2. **ハーネス整合性の検証**:
   - `.venv/bin/python3 scripts/validate-harness.py` を実行し、命名規則、常駐予算、リンク切れ等がないか確認する。
   - 必要に応じてテストを実行する。
3. **結果の要約報告**:
   - 撤廃したワークアラウンド / 削減した行数・トークン
   - 新たに活用した新機能
   - 残る未検証事項や次の実行時の留意点
