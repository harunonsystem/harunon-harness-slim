# Issueの文脈

Issueが指定されたときだけ読む。trackerはユーザー・プロジェクト指定を使う。

1. 今回のIssue本文と受入条件を確認する。既に取得済みで変更がない資料は再取得しない。
2. 親Issueがあり、仕様・命名・スコープの合意が親にある場合はその部分を読む。
3. 兄弟Issueは今回の契約に関わるものだけ取得する。全兄弟を再帰的に列挙しない。
4. 命名・URL値・型・除外事項を差分に照合し、食い違いをfile:line付きで記録する。

Issueが指定されず会話で受入条件が揃う場合、tracker探索は不要でカテゴリ1はN/A。
必須の仕様が外部Issueにあり取得できない場合は確認不可。取得できた範囲と不足を明示し、PASSEDにしない。
