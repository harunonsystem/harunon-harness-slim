# 日本語の文章の確認

日本語の文章を、次の2段階で確認する。

1. 文章が、表記・文の長さ・禁止語等の機械的に判定できる規則に違反していないかを、textlintで検査する
2. 文章を書いた経緯・意図を知らない別のエージェント（以下、レビューするエージェント）に、textlintで判定できない規則に従って文章をレビューさせる（以下、AIレビュー）

## 準備

bunが無い場合は、作業を止めてユーザーに確認する。

このSKILL.mdがあるディレクトリで、ロックファイルどおりに依存パッケージをインストールする。
このインストールはgitで管理しているファイルを変更しないため、ユーザーの確認を取らずに実行してよい。

```sh
bun install --frozen-lockfile --production
```

## 手順

### 1. 検査対象の文章をファイルに書き出す

textlintとAIレビューは、どちらもファイルを対象にする。
リポジトリの規約に一時ファイルを置くディレクトリの定めが無い場合は、そのディレクトリをユーザーに確認する。
コミットメッセージ・Issue・Pull Requestの本文のようにファイルが無い文章は、作業中のリポジトリで一時ファイルを置くディレクトリにMarkdownファイルとして書き出す。

対応する拡張子（[@cffnpwr/textlint-plugin-comments](https://github.com/cffnpwr/textlint-plugin-comments/blob/main/packages/plugin-comments/README-ja.md#対応する言語)）のソースコード・設定ファイルは、textlintがコメントの部分だけを検査する。
対応していない拡張子のファイルのコメントは、Markdownファイルに書き出して検査する。

### 2. textlintで検査する

次のコマンドは、このSKILL.mdがあるディレクトリで実行する。
作業中のリポジトリに独自のtextlint設定（`.textlintrc`・`.textlintrc.json`等）がある場合は、`--config`の値をその設定ファイルの絶対パスに置き換える。

```sh
# ファイルを検査する
bun x textlint --config .textlintrc.json /absolute/path/to/file.md

# 自動修正できるエラーを修正する
bun x textlint --fix --config .textlintrc.json /absolute/path/to/file.md
```

- `error`は修正する
- `warning`は、指摘された問題が実際に文章にあると判断した場合に修正する。修正しない場合は、理由をユーザーに伝える

### 3. AIレビューを依頼する

textlintのエラーを修正した後、レビューするエージェントに文章をレビューさせる。
サブエージェントを使えるハーネスでは、サブエージェントにレビューさせる。
サブエージェントを使えない場合は、新しいセッションでのレビューをユーザーに依頼する。
依頼するときは、そのセッションのエージェントに渡すパスと指示（この節の後半に示す）もユーザーに伝える。
レビューするエージェントのモデルには、Claude Haiku・GPT-6 Luna等の軽量モデルを指定する。

レビューするエージェントに渡す情報は、次の2つのパスと、この節の最後に書いた指示だけにする。
文章を書いたエージェント自身がレビューすると、書いた意図を知っているため、読み手が補えない省略を見落としやすいためである。
文章を書いた経緯・意図・直前の会話は含めない。

- 検査対象のファイルのパス
- [references/review-prompt.md](references/review-prompt.md)のパス

レビューするエージェントには、次の2点を指示する。

- `references/review-prompt.md`の規則に従って、検査対象のファイルをレビューすること
- `references/review-prompt.md`の「出力」の節が定める形式に従って、結果を返すこと

検査対象がソースコード・設定ファイルの場合は、コメントの部分だけをレビューすることも指示する。

### 4. 指摘に対応する

AIレビューで指摘された箇所を修正した後、textlintで再び検査する。
AIレビューの指摘が誤りだと判断した場合は、修正せずに、その指摘の内容と、誤りだと判断した理由をユーザーに伝える。

## 誤検出の抑制

textlintが妥当な内容（固有名詞・コード中の用語・意図した書き方）をエラーとして報告した場合は、抑制コメントを使う。
抑制コメントを追加する前に、該当する箇所・規則名・誤検出と判断した理由をユーザーに示し、許可を得る。

```markdown
<!-- textlint-disable rule-name -->

誤検出された内容。

<!-- textlint-enable rule-name -->
```

1行だけを対象にする場合は次のように書く。

```markdown
対象の行。 <!-- textlint-disable-line rule-name -->
```

規則に合わせるためだけに、意味の変わる言い換えをしない。
