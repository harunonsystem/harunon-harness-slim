# explain-before-shorten

`yomiyasu` は利用可能な場合だけ使用する。未導入の場合は、各制約を保ち、その場で表現だけを推敲する。

AI が生成しがちな不自然・文脈不足な説明文（「言葉や文字数だけを削って意味が通じない」「いきなり否定から入る」等）を、口頭説明のプロセスを挟むことで改善するスキル。

文章全体の文法・比喩・AI臭さの推敲は `yomiyasu` に任せ、長文の論証構成は `japanese-tech-writing` に任せる。本スキルは、**要約・箇条書き・スライドなどの短い説明文において、意味を保ったまま的確に圧縮する思考プロセス**を担当する。

## コア思想: Explain Before Shorten

> **「短く書く」より先に、「相手に口頭でどう説明するか」を考える。**

単に文字数を削ったり体裁を整えようとすると、文脈や前提条件が抜け落ち、ロボット調の不親切な文章になる。
まず「隣の人に対面で口頭で説明するならどう伝えるか」という自然で論理の通った文章を組み立て、その本質的な意味を落とさずに短く整える。

## 手順

### 1. 何を伝えたいかを決める
- 読み手・聞き手に理解してほしい要点を1〜2点に絞る。
- 仕組み、利用条件、例外、注意点など、異なる話を1つの文に無理に詰め込まない。

### 2. まず口頭ならどう説明するかを考える
- 文字数を気にせず、目の前の人に話しかけるように「何がどうなるか」「なぜそうなるか」を論理的に組み立てる。
- 主語と述語の対応を明確にし、唐突な否定（例:「〜を意味するわけではない」）で始めず、まず肯定的・具体的に何であるかを述べる。

### 3. 意味を保って短く整える
- 専門用語や重要な条件（前提・制約・数値）は勝手に削らずに保持する。
- 口頭説明で通った因果関係や文脈を壊さずに、冗長な言い回しや重複表現だけを削って端的に落とし込む。

## 適用例（Before / After）

- **Before（AI が作りがちな不親切な短縮文）**:
  > Completed はコードが最後まで実行された状態。入力不正が0件を意味するわけではない。
- **After（口頭説明を経て短く整えた文）**:
  > Completed とはコードが最後まで実行された状態を指します。ただし、入力値の不正などが一切なかったことまで保証するものではありません。

- **Before（抽象化しすぎて動作が伝わらない文）**:
  > 受付と完了確認を分離する。
- **After（口頭説明を経て具体を残した文）**:
  > 処理の終了を待たずに受付完了を返し、処理結果は後から問い合わせる方式にする。

## 棲み分け

| スキル | 担当領域 |
| --- | --- |
| **`explain-before-shorten`** | 短文要約・箇条書き・スライド説明。口頭思考による文脈保持と圧縮 |
| **`yomiyasu`** | 日本語表現全般の推敲。不自然な比喩・主述不一致・AI臭さの除去（情報の不増補・意味保持） |
| **`japanese-tech-writing`** | 長文技術文書・書籍原稿の論証構成、パラグラフライティング |
