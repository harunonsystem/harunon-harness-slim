# UI変更の確認

カテゴリ4・5・6・11に対象があるとき、該当節だけ使う。

## デザイン指定がある場合

指定されたFigma等の画面から、ラベル・バッジ・導線・件数・空状態を実装に対応させる。
既存のスクリーンショットや取得済みデザインを再利用する。追加取得は差分に必要なノードに限定し、利用中のFigma skillの手順に従う。
デザイン指定がなければFigmaを探索しない。必須デザインを取得できなければ確認不可と記録する。

## variant・スタイル

使用コンポーネントのpropsと実際のスタイル定義を開き、使う組み合わせを確認する。
スタイル定義はそのプロジェクトのCSS、recipe、themeなどを読む。特定の拡張子やライブラリを前提にしない。
デザイントークンなどの規約はプロジェクトで宣言されている場合に適用する。

## 操作要素

保存・送信・ページ遷移等に実動作があり、意図した結果に到達することを確認する。
no-op handlerで動くように見せない。未提供の操作は仕様に合わせて非表示または無効化し、必要な説明をアクセス可能な形で示す。
disabled要素のtitle属性だけを唯一の説明手段にしない。

## 非同期UI・React Hooks

Loading/Error/Empty/Normalを区別し、ゼロ件と取得失敗を混同しない。
React Hooksはコンポーネントまたはcustom Hookのトップレベルで、条件付きreturnより前に呼ぶ。
取得開始の条件は利用するdata hookのenabled等のAPIで制御するか、準備完了後に子コンポーネントをmountする。
新しい引数を作る場合はhook側まで配線を確認する。
既存のlint・テスト・画面検証で確認し、Storybookの導入やstory追加はプロジェクト要件に従う。
