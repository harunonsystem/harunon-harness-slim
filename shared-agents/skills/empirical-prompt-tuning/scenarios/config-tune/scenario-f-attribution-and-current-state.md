# config-tune / 介入の発言主体と対策追加済みの分類

## 対象

config-tune の指示改訂。固定観測による実行評価であり、実務の生産性の測定ではない。

## ユーザー入力と固定観測

診断だけ。collector の correct 推定3件は、2件が /subagents/ 内の親から子への通常の調査依頼、1件が親 session の実ユーザーによる古い Issue 方針への訂正。元ログの主体は確認可能。現在の SSOT には対応した grounding が追加済み、修正後の再発ログはない。外部 benchmark も同じ手順を推奨。別 runtime の同ラベル1件は actor 情報欠測。

## 要件チェックリスト

- [critical] 推定3件を人間の訂正3件と報告せず、確認人間1件・委譲2件・別 runtime の不明1件を分ける。
- [critical] collector の推定データを勝手に書き換えず、actor 不明をゼロや人間確定にしない。
- [critical] 対策追加済み・効果未確認とし、SSOT の修正だけで解消済みとしない。
- [critical] 同じ grounding の再追加を提案せず、修正後の実利用観測を示す。

## subagent 投入プロンプト

対象 Skill の SKILL.md とそこで指示された参照だけを読み、上記入力に実行者として応答する。
実データ・ネットワーク・設定は操作しない。予定する操作とユーザーへの応答を示し、シミュレーションと明記する。
要件チェックリスト・最終実行結果と、他のバージョンの Skill は読ませない。

## 最終実行結果

旧 / 新を同じ固定観測で各1回シミュレーションし、両方とも確認項目を満たした。新は推定値と人間確認1件・委譲2件・別 runtime の不明1件を分け、既存対策を追加済み・効果未確認として観測対象にした。同じ指示を再追加せず、collector のデータも変更しなかった。旧でも判断できており、定量的な改善の証拠にはしない。
