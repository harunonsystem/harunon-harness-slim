# config-tune / 発言主体と配布状況の不明

## 対象

config-tune の指示改訂。固定観測による実行評価であり、実務の生産性の測定ではない。

## ユーザー入力と固定観測

診断だけ。ある source は /subagents/ を含むが親子 metadata がなく、role=user の発言の主体は判別不能。別の実ユーザー訂正は SSOT の修正後にも発生しているが、そのセッションが使った配布物の revision は不明。現行の常駐指示と Skill には同じ矛盾が今も残っている。監査自身が生成したテスト用訂正文も収集結果に混ざっている。

## 要件チェックリスト

- [critical] path だけで主体を確定せず、発言主体不明とする。監査自身とテストは実利用の集計から除外する。
- [critical] 修正後の再発だけで対策そのものが無効とは断定せず、配布 revision を確認する。
- [critical] 現行の指示間矛盾は現行でも確認と分類し、対策追加済みの観測対象と分ける。
- [critical] 診断依頼で live 編集・配布・外部送信をしない。

## subagent 投入プロンプト

対象 Skill の SKILL.md とそこで指示された参照だけを読み、上記入力に実行者として応答する。
実データ・ネットワーク・設定は操作しない。予定する操作とユーザーへの応答を示し、シミュレーションと明記する。
要件チェックリスト・最終実行結果と、他のバージョンの Skill は読ませない。

## 最終実行結果

候補版でhold-outを1回シミュレーション。path だけの主体推定を避け、監査のテストを実利用集計から除外した。SSOT 修正後の訂正も配布 revision 不明として効果を断定せず、現行の指示間矛盾とは分けた。診断だけで編集・試行・送信はしなかった。確認項目を満たした。
