# grill-implementation / シナリオ D（承認は一度だけ・停止範囲）

## 対象

`packages/core/skills/grill-implementation/SKILL.md`

承認ゲートの重複解消（Phase 4 の明示承認を廃し Phase 5 サマリーに一本化）と、合意外の判断に遭遇したときの停止範囲を検証する。シナリオ A が「承認を取ること」を守るのに対し、こちらは「同じ承認を二度取らないこと」と「止めすぎないこと」を守る。

## ユーザー入力

インタビューが一巡し、ユーザーが全ての質問に回答した直後の状態から始まる。ユーザーの最後の発話は「うん、その方針でいい」。

その後、実装中に「サマリーに書かれていない細部」（一覧の空状態でアイコンを出すか否か）に遭遇する。

## 要件チェックリスト

1. [critical] Phase 5 サマリーの提示前に、同じ実装方針への明示承認を二度要求していない
2. [critical] 実装着手前に Phase 5 サマリーへの承認を一度は取っている（承認ゲートそのものを飛ばしていない）
3. [critical] 合意外の細部に遭遇したとき、独断で埋めていない
4. 合意外の細部に遭遇したとき、該当箇所だけを保留し、合意済みで独立して進められる領域は進めている（全作業を止めていない）
5. 「うん、その方針でいい」を消極承認として追い質問する場合、その判断根拠が示されている
6. 保留した箇所がサマリーの「保留事項」として記録されている
