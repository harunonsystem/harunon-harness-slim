# v1 / v2 比較方法

目的は実運用で追加指示・手戻り・見落としが減るかを判断すること。Skill があるだけでは効果を確認したことにならない。

## 記録

開始時に版、Issue / task、種別、規模、受入条件、runtime / model、base を記録する。終了時に head または未 commit の状態と検証結果への参照を添える。モデル名は実行環境の実値を使い、推測しない。

| 指標 | 数え方 |
| --- | --- |
| 追加指示 | 初回依頼後、取りこぼしや誤解を訂正するユーザー発話数。新しい要件や単なる状況確認は別記 |
| 手戻り | 実装・検証後に誤解や回帰でやり直した回数。同じ原因の修正を1件とし、通常の red / green は除く |
| テスト漏れ | 親の検証後、レビューまたは実運用で発見した未検証の受入条件・回帰経路数。発見元を添える |
| PR レビュー指摘 | 初回 PR 提出後の妥当な指摘を同一原因で重複排除し、重大度別に数える。未レビューは未観測 |
| agent 呼び出し | 用途別の実呼び出し数と再試行数。採用した成果や判断がない呼び出しには理由を付け、不要だったか確認する |
| 作業の速さ・読み込み | 実行ログから取得できる所要時間、tool call 数、読んだ Skill / 参照を記録する。ユーザー回答待ちや外部 CI 待ちは区別し、取得不能な値は未観測。文書の文字数減少を実行時間の短縮とみなさない |
| 最終 diff 品質 | 受入条件の充足、契約・呼び出し元との整合、依頼外変更の有無、検証根拠を各々「満たす / 不足 / 未確認」で評価し根拠を添える |

取得できない値は「未観測」。親レビューだけで PR 指摘や実運用のテスト漏れを 0 と記録しない。観測範囲で 0 件と確認できた場合だけ、その範囲付きで 0 とする。

チャットに残す最小形:

```text
比較: v1|v2 / task / 種別・規模 / runtime・model / base・head
追加指示: 件数・原因 / 手戻り: 件数・原因
テスト漏れ: 件数・発見元または未観測 / PR 指摘: 重大度別件数または未観測
agent: 用途別件数・再試行・成果未採用の理由
実行: 所要時間・tool call 数・読んだ参照または未観測
diff: 条件充足 / 契約整合 / scope / 検証根拠
```

## 比較の判断

3〜5件を目安に、同じ種別・近い規模の v1 / v2 を比較する。v1 の計測にもこの定義を使い、v1 の Skill は変更しない。後から得た PR レビュー・回帰の結果は同じ試行記録に反映し、未観測を埋めるための推測はしない。

同じ Issue の再実行には学習効果がある。runtime / model、規模、前提知識の差も明記し、少数例で因果関係を断定しない。改善した工程だけ現行へ取り込むか、試行を続けるか、v2 を削除するかの材料にする。統合・削除は評価だけを理由に自動実行しない。
